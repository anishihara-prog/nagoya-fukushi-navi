# 障害福祉支援ナビ なごや(試作版)

名古屋市の障害者相談員の方が、福祉サービス・必要な手続き・ケースに応じた支援を検索できるツールの試作版です。
ビルドツール不要(npm install なし)の、HTML / CSS / 素のJavaScriptだけで作られています。

## フォルダ構成

```
nagoya-fukushi-navi/
├── index.html          ← アプリ本体(これをブラウザで開く)
├── css/style.css        ← デザイン
├── js/
│   ├── data-store.js     ← データの読み込みだけを担当する層(将来差し替え用)
│   └── app.js            ← 検索・ケース相談のロジック
└── data/entries.json     ← サンプルデータ(福祉サービス・手続き 10件)
```

## VSCodeでの開発の始め方

1. このフォルダをVSCodeで開く(「フォルダーを開く」)
2. `index.html` を直接ダブルクリックでは**開かないでください**(`file://` で開くとデータの読み込みに失敗します)。
   代わりに、以下のどちらかの方法でローカルサーバーを立てて開いてください。
   - **VSCode拡張機能「Live Server」を入れている場合**: `index.html` を右クリック →「Open with Live Server」
   - **拡張機能を入れたくない場合**(ターミナルで):
     ```
     cd nagoya-fukushi-navi
     python3 -m http.server 5500
     ```
     ブラウザで `http://localhost:5500` を開く
3. ブラウザが開いたら、タブを切り替えて動作を確認してください。
   - 🔍 検索する: キーワード・分類で絞り込み
   - 🧭 ケースから探す: 障害種別・年代・困りごとのチップを選ぶと、当てはまる支援が表示される

## データの更新について(重要)

このアプリは検索専用(読み取り専用)です。アプリ内から情報を追加・編集する機能はありません。

データを追加・修正したいときは、`data/entries.json` を直接編集してコミット・pushしてください
(Claude Codeに「〇〇を追加して」のように依頼して編集してもらうこともできます)。
GitHub Pagesはpush後に自動で再デプロイされるため、他の利用者も次にページを開いた/リロードした
タイミングで最新の内容を見られます(ローカルキャッシュは持たないため、反映のための特別な操作は不要です)。

## 次の段階(アプリ内での編集を復活させたくなったら)

今は「複数人が同時にアプリ内から編集する」という使い方は想定していません。
将来やはりアプリ内から直接編集したくなった場合は、以下のような小さなバックエンドが必要になります。

- 簡単なAPIサーバー(Node.js + Express など)を1つ用意する
- データはサーバー側のデータベース(SQLiteなど、小規模なら十分)に保存する
- `js/data-store.js` の `loadEntries` の中身を、`fetch('data/entries.json')` の代わりに
  `fetch('/api/entries')` を呼ぶ処理に書き換え、保存用の `saveEntries` 相当の関数を追加する
- `app.js` 側に登録・編集フォームを作り直す必要があります

その先、名古屋市の正式なツールとして全相談員に展開する場合は、データの安全な保管・アクセス権限・
アクセシビリティ対応などの観点から、市の情報システム部門との連携・正式な手続きを検討することをおすすめします。

## 個人情報の取り扱いについて(必ずお読みください)

このツールは「制度・サービスの一般的な情報」を検索するためのものです。
相談者個人を特定できる情報(氏名・住所・個別の相談記録など)は、**入力しないでください**。
特に将来「全相談員で共有」する形にした場合、入力した情報は他の利用者にも見える想定で設計されています。

## サンプルデータについて

`data/entries.json` に入っている10件は試作用のサンプルです。内容は一般的な公開情報を参考に作成していますが、
実際の運用前には、各区役所・基幹相談支援センター等で最新の正確な情報に必ず更新してください。

## リンク切れ・HP更新の検知

`data/entries.json` の `welnetUrl` / `extraLinks` に登録した外部リンクを毎週月曜(GitHub Actions)に自動巡回し、
前回チェック時との比較で次の変化を検知します。

- リンク切れ(HTTPエラー・到達不能)
- リンク先URLの変更(リダイレクト先が変わった)
- ページ本文の更新(本文テキストのハッシュが変化した)

変化があった場合のみ GitHub Issue が自動作成され、`anishihara-prog` が担当者(assignee)に設定されます。
状態は `data/link-check-state.json` にコミットされ、このファイルの git 履歴が「いつ何が変わったか」の記録になります。

### Gmailで通知を受け取るには

GitHub独自の通知メール機能を使うため、追加のコード・シークレット設定は不要です。次を確認してください。

1. GitHubアカウントの通知先メールアドレスにGmailアドレスを登録する
   (Settings → Emails でGmailアドレスを追加し、Settings → Notifications → 「Notification email」で選択)
2. Settings → Notifications で「Issues」のメール通知が有効になっていることを確認する
   (「担当者に指定されたIssue」は既定の "Participating and @mentions" でも通知対象)

これで、自動作成されたIssueに `anishihara-prog` が担当者として設定されるたびにGmailへメールが届きます。
担当者を変える場合は `.github/workflows/check-links.yml` の `--assignee` を書き換えてください。

手動で実行する場合:

```bash
npm run check-links
```

ワークフロー定義: `.github/workflows/check-links.yml`(手動実行は Actions タブから `workflow_dispatch` でも可)。
本文ハッシュ比較のため、対象ページの軽微な表記ゆれ(日付表示など)でも「更新あり」と誤検知することがあります。
実際に内容を確認したうえで、必要なら `data/entries.json` の該当項目を更新してください。
